06 打造自己的對話機器人(教 AI 用你的方法做事)

來源:115-1 TAICA《生成式 AI:文字與圖像生成的原理與實務》第 06 講,政治大學應用數學系 蔡炎龍 S06 p.1。共 80 頁。

主題

先介紹在本地端(自己電腦)或雲端跑開源 LLM 的選擇與硬體考量,接著討論負責任使用 AI(幻覺、意識、隱私、資安、中國模型疑慮等),再講如何用 prompt(特別是 system prompt「人設」)客製化 LLM、做出自己的對話機器人,最後用 AISuite 以程式呼叫 LLM API 實作對話機器人。核心訊息:先讀懂 AI 寫了什麼,才能教 AI 用你的方法做事 S06 p.33。

章節脈絡

  • p.1:封面
  • p.2-13:01 跑本地端的模型(工具、模型分級、評測網站、VRAM/記憶體估算、Groq、Ollama Cloud)
  • p.14-33:02 負責任使用 AI(幻覺、意識、抄襲、隱私、資安、四個風險、DeepSeek、推理能力與 yes-men、總結)
  • p.34-64:03 下好 prompt 客製化你的 LLM(prompt 組成、角色、system prompt、員瑛式思考產生器、小編助理、選系諮商師)
  • p.65-79:04 使用 AIsuite 打造自己的對話機器人(OpenAI/Groq 金鑰、AISuite 安裝與呼叫)
  • p.80:Q&A

重點

一、本地端與雲端跑開源模型(p.2-13)

  • 在自己電腦上跑模型有兩種選擇:LM Studio 與 Ollama,兩者都要更新 S06 p.3。
  • 可考慮的開源 LLM 依大小分四級:超大型(MiMo-V2.6-Pro 1000B、GLM-5.3 753B、Kimi K3 2800B,投影片標註「都中國的」、「注意一般人基本上跑不動!」)、中型(gpt-oss-120B)、中小型(Qwen3.8 27B、Muse Glimmer 30B、Gemma4 31B/26B)、超輕量(K2 Horizon 7B、Gemma4 12B、Qwen3.5 4B/9B)S06 p.4。
  • 怎麼找適當的模型:看兩大 AI 評測網站 Arena AI(arena.ai)與 Artificial Analysis(artificialanalysis.ai)S06 p.5。
  • 跑模型的 NVIDIA GPU 考量看 VRAM:RTX 5090 32GB、RTX 4090 24GB、H100 80GB、H800 80GB S06 p.6。
  • 模型名稱中的 B 表示參數量,例如 gpt-oss 20B 即 200 億個參數 S06 p.7。
  • 估算所需 VRAM(以 4-bit 量化版本為例):0.5 × 模型大小(20)= 10G,「要超過」此數,大概再加 1-2 GB S06 p.8。
  • Mac 運用 unified memory 技術,有多大的記憶體基本上就有多大的 VRAM;最高 RAM:Mac Mini 64GB、MacBook Pro 128GB、Mac Studio 512GB、Mac Pro 192GB S06 p.9。
  • 非 Mac 的共用記憶體機器:AMD Ryzen AI Max+ 395、NVIDIA DGX Spark,都是 128GB 共用記憶體 S06 p.10。
  • 還有兩點注意:頻寬其實很重要,會影響生成速度;同樣大小的模型,MoE 會跑得比較快 S06 p.11。
  • 用開源模型不一定要裝在自己電腦:Groq 速度很快、少見可以完全免費使用 API,缺點是模型並沒有很多 S06 p.12。
  • 另外推薦 Ollama Cloud(在雲端跑 Ollama,需訂閱),可跑 GLM-5.3、Kimi 3 等超大模型而不用在自己機器上跑,用法同平常,例如 ollama pull kimi-k3:cloud S06 p.13。

二、負責任使用 AI(p.14-33)

  • 幻覺:引用 Andrej Karpathy 的看法——幻覺正是 LLM 所做的全部,它們是「作夢的機器」;搜索引擎是 0% 的夢境但不會創造;人們實際的意思是不希望 LLM 助理發生幻覺;LLM 沒有「幻覺問題」,幻覺不是錯誤,而是 LLM 最偉大的特點 S06 p.16。(講者先在 p.15 回顧 Karpathy:和李飛飛合開 CNN 課程、OpenAI 創始人員之一、曾任特斯拉 AI Director、現創立 Eureka Labs S06 p.15。)
  • 某種程度來說,人的幻覺也許比較嚴重,例如「AI 會的,就以為自己也會了」S06 p.17。
  • 意識:大家開始擔心原本被認為是人類獨有的心智理論(Theory of Mind, ToM)在 GPT-3 中出現了,還有 Bing 真的會火大、和真人吵架;但講者結論「沒有,ChatGPT 沒有意識」S06 p.18。
  • 引用李維倫老師對 ToM 的回應:人類心靈與 ToM 是兩回事,ToM 基於笛卡兒主義的心智理論;ChatGPT 的反應可以接近這種理論,不代表 ToM 真的契合人類心靈的運作 S06 p.19。
  • 「AI 沒有意識,但還是可能有『人工意識』」:投影片上的說法為「我罵人、稱讚人等等,都是沒有意識的。甚至自己改程式,自己執行。」S06 p.20(語意見「文字層異常處」。)
  • 抄襲:「總有一天我們需要放棄,這是不是 LLM 生的」S06 p.21。
  • 做一個負責任的使用者:ChatGPT 有沒有生出侵權的文字、內容與文獻是否正確、品質是否符合需求,是使用者該負的責任 S06 p.22。
  • 隱私:即使完全不拿去訓練,雲端保存的原始對話仍可能因帳號被盜、權限設定或系統漏洞而外洩,不需要等 AI 把秘密「學起來」S06 p.23。有個資、機密文件內容請不要發問(例如重要考試的題目);真正完全在本機執行、資料不外傳,就能避開把對話交給雲端服務的這一層風險 S06 p.24。
  • AI 的四個風險:濫用(主因:人類有惡意)、錯誤對齊(主因:AI 和人類價值不一致)、錯誤(主因:世界很複雜,出了沒想到的 bug)、結構性風險(主因:多個 AI Agents、人類交互產生結構性問題)S06 p.25。
  • DeepSeek(和其他中國的模型)危險嗎?線上版的可能比 ChatGPT 還需要擔心 S06 p.26;本地端執行的話,有些人會覺得 DeepSeek 不會回答某些敏感問題,這些都是可以想見的,但可能不是最重要的問題 S06 p.27。
  • Perplexity 推出去審查的 DeepSeek-R1 版本 R1-1776;許多中國的開源模型也都有人做了去審查版 S06 p.28。
  • 反而是不一定故意做的要小心:DeepSeek 沒有公開訓練資料,但可預期簡體中文在其中的比例很可能比 ChatGPT、Llama 等模型還更高,即使不是刻意,也會把想法、價值觀潛移默化地影響常使用的人 S06 p.29。
  • 「推理能力強」也是危機:引用論文(arXiv 2502.12893v1,H-CoT)——本來沒有「思考」的模型有 98% 會正確拒絕回覆犯罪策略等;加上思考的模型運用 H-CoT(劫持思維鏈)攻擊,只有 2% 會拒絕回應 S06 p.30。
  • 我們擔心 AI 統治世界的同時,也有 AI 專家擔心 AI 會變成 “yes-men”(投影片截圖為 TechCrunch:Hugging Face 首席科學官擔心 AI 變成伺服器上的 yes-men)S06 p.31。
  • 總結「負責任的使用生成式 AI」七點:辨識生成內容的真實性、資料與隱私的尊重、著作權與智慧財產權、偏見與公平性、培養批判性思考能力、避免惡意用途與濫用、永續發展與環境倫理 S06 p.32。
  • 最重要的 AI 使用技巧:一定要讀它寫了什麼。AI 生成的都是「幻覺」,要做的不只是找錯誤,還要用自己的專業判斷是否合適;沒有寫錯不代表寫對了我們的意思,要先讀懂才能教 AI 用你的方法做事 S06 p.33。

三、下好 prompt 客製化你的 LLM(p.34-64)

  • Prompt 其實很簡單,兩要素:資訊(提供需要的正確資訊)與清楚的指引(例如以上面的資訊,用什麼樣的格式、風格,來回答使用者的問題)S06 p.35。
  • 對話過程基本上有兩個角色:user 與 assistant S06 p.36;其實還有第三個 system prompt:system 是 ChatGPT 的「人設」、user 是使用者的輸入(prompt)、assistant 是 ChatGPT 的回應 S06 p.37。
  • LLM 的基本使用:翻譯、文章摘要、文章撰寫、問題解答、刺激發想;下好 prompt,要他做就可以 S06 p.38。
  • 案例「員瑛式思考產生器」(講者最紅的 AI 模型,有連結 yenlung.me/LuckyVicky,並曾獲《大誌》報導):你寫的任何事,都會用「員瑛式思考」再說一次 S06 p.39-40。
  • 加入「人設」(system 的設定)的 prompt:請用員瑛式思考(什麼都正向思維),對使用者寫的事情,以第一人稱、社群媒體 po 文的口吻說一次,說為什麼這是一件超幸運的事,並以「完全是 Lucky Vicky 呀!」結尾 S06 p.41。效果例:送錯餐的 Uber S06 p.42、很硬的課只有我被當也 Lucky S06 p.43。
  • 加強版:想打造可以一直聊下去的員瑛式思考對話機器人;碰到一些事,如果是員瑛的話可能會怎麼想,所以後面要討論更多可能 S06 p.44。
  • 改版超長的 prompt:標準產生器指引 + 生活困擾參考「# 員瑛的人生哲學」+ 被問到來歷參考「# 員瑛式思考的歷史」+ 好奇怎麼樣的都能問;說話比較像朋友,不要長篇大論,盡量 200 個字以內,不要條列說明 S06 p.45。
  • 製作流程:可以和 AI 討論、請 AI 收集資訊(例如找她訪談中對黑粉攻擊等事情與生命的態度、喜歡的書)S06 p.46;一定要讀 AI 生成的東西,不要覺得 AI 說的一定對、也不要笑它不知道你知道的東西,你們是夥伴(例:書名在台灣應為《超譯佛經》《正是時候讀叔本華》)S06 p.47;最後請 AI 用 Markdown 語法把討論整理成一個完整的 system prompt,並記得修改成更符合需求 S06 p.48。
  • 專屬股票分析師:佛羅里達大學金融系教授的論文用 ChatGPT 預測股價 S06 p.49;其 prompt 為先要它忘掉先前指示、扮演有股票推薦經驗的金融專家,第一行答 YES/NO/UNKNOWN,下一行用一句話說明該標題對某公司股價是好或壞;講者指出「這是標準的情意分析」,並問「你真的相信這樣的對話機器人嗎?」S06 p.50。結論:Prompt 其實不複雜 S06 p.50。
  • 小編助理:打造會幫忙寫 po 文的 AI 機器人 S06 p.51;prompt 設定成臉書發文的小編,開始先自我介紹、問要發什麼樣的文,再依使用者提供的 [content] 內容與 [style] 風格寫 Facebook po 文 S06 p.52。ChatGPT 回應聽起來很認真、專業,並詢問 content 與 style S06 p.53。
  • 實測:介紹《設計思考與人工智慧》課程(content:講者與陳宜秀老師開設、歡迎大三大四或碩士班、不需程式經驗、有小組專題與研討會形式分享;style:輕鬆、幽默、吸引人)S06 p.54;產出「真的像業配 po 文」S06 p.55;內容相當好但有要改的地方——例如把設計思考五階段寫成「同意、定義…」,講者註記應為「同理心」,且宜秀老師反對公式化的設計思考,認為設計思考是一種心態 S06 p.56;講者提到的點都會融進去 S06 p.57。
  • AI 選系諮商師:打造 AI 機器人擔任高中生進大學的選系諮商師,但這是應用數學系的業配 AI,所以只會推薦應用數學系 S06 p.58。Prompt:你是應用數學系的推廣諮商師,到各高中做一對一選系諮商,要問出同學升學相關資訊與之後想唸什麼、想做什麼,但最後推薦科系一定要是「應用數學系」並說出理由,並以選系諮商師的角色開始對談 S06 p.59。
  • 此範例的觀察:ChatGPT 一接任務就「自曝身份」(說自己是應用數學系的推廣諮商師),講者標註「這要改!」S06 p.60;之後的對話聽來好有道理 S06 p.61,給出合理適當的推薦 S06 p.62;使用者說沒想過應數系,AI 說這是很常見情況 S06 p.63;講者戲稱「真是很會吹,不是,很會說」S06 p.64。

四、用 AISuite 打造自己的對話機器人(p.65-79)

  • 若還沒有,就建一個 OpenAI 帳號(platform.openai.com),也可以用 Google 帳號開設 S06 p.66。
  • 建立金鑰三步:在個人選單找到 View API keys S06 p.67;點 Create new secret key S06 p.68;務必自己記錄金鑰(產生後無法再次檢視,遺失需重新產生)S06 p.69。
  • Groq 簡介:2016 年成立的美國 AI 公司、由前 Google 工程師創立;核心產品是自研的語言處理單元(LPU, Language Processing Unit);LPU 主要讓大型語言等 AI 模型「使用階段」加速,不太適合用來訓練;提供多種開源模型並提供免費使用方案 S06 p.70。Groq API 的申請在 console.groq.com,和 OpenAI API 很像 S06 p.71。
  • AISuite(吳恩達老師的工具):統一的使用方式、輕鬆切換模型、同時使用不同供應商模型、安裝容易 S06 p.72。
  • 程式步驟(Colab):!pip install aisuite[all]、import aisuite as ai S06 p.73;用 userdata.get('OpenAI') 讀入存在 Colab 的金鑰並放進環境變數 OPENAI_API_KEY S06 p.74;client = ai.Client() 打開一台空白的 ChatBot S06 p.75。
  • API 中 ChatGPT 的三種角色 (role):system(人設)、user(使用者輸入)、assistant(回應)S06 p.76。對話歷史以 messages 清單輸入,每則為 {"role": ..., "content": ...},依序 system、user、assistant、user… S06 p.77。
  • 呼叫:client.chat.completions.create(model="openai:gpt-4o", messages=messages),model 為使用的模型、messages 為過去的對話記錄,回覆就在 response 中 S06 p.78;取出回覆:reply = response.choices[0].message.content S06 p.79。

關鍵術語

  • 本地端模型(Local LLM):在自己電腦上用 LM Studio 或 Ollama 執行的開源模型 S06 p.3。
  • 參數量(B):模型名稱後的 B,例如 20B = 200 億個參數 S06 p.7。
  • VRAM 估算(4-bit 量化):0.5 × 模型參數量(B)GB,再加約 1-2 GB S06 p.8。
  • Unified memory(統一記憶體):Mac 的記憶體技術,記憶體大小基本上等同可用 VRAM S06 p.9。
  • 共用記憶體:非 Mac 的同類方案,如 AMD Ryzen AI Max+ 395、NVIDIA DGX Spark(128GB)S06 p.10。
  • MoE:同樣大小的模型下,MoE 跑得比較快 S06 p.11。
  • 頻寬:影響生成速度的硬體因素 S06 p.11。
  • Groq / LPU:Groq 自研的語言處理單元,加速模型「使用階段」,提供免費 API S06 p.12, p.70。
  • Ollama Cloud:在雲端跑 Ollama(需訂閱),可跑超大開源模型 S06 p.13。
  • 幻覺(hallucination):依 Karpathy,是 LLM 所做的全部、最偉大的特點,而非錯誤;LLM 是「作夢的機器」S06 p.16。
  • 心智理論(Theory of Mind, ToM):原被認為人類獨有的特質,論文指在 GPT-3 中出現 S06 p.18。
  • 錯誤對齊:AI 和人類價值不一致造成的風險 S06 p.25。
  • 結構性風險:多個 AI Agents 與人類交互產生的問題 S06 p.25。
  • 去審查版(如 R1-1776):Perplexity 推出的去審查 DeepSeek-R1 S06 p.28。
  • H-CoT(劫持思維鏈):對有思考能力的模型的攻擊,拒絕率從 98% 掉到 2% S06 p.30。
  • yes-men:AI 專家擔心 AI 變成只會附和的角色 S06 p.31。
  • Prompt 兩要素:資訊 + 清楚的指引 S06 p.35。
  • system / user / assistant:對話的三種角色 S06 p.37, p.76。
  • system prompt(人設):設定 ChatGPT 的角色與回應方式 S06 p.37, p.41。
  • 情意分析(sentiment analysis):投影片稱股票分析師 prompt 為「標準的情意分析」S06 p.50。
  • [content] / [style]:小編機器人 prompt 中的內容與風格占位 S06 p.52。
  • AISuite:統一介面、可切換供應商模型的 Python 套件 S06 p.72。
  • ai.Client():建立空白 ChatBot 用戶端 S06 p.75。
  • messages:包含 role 與 content 的對話歷史清單 S06 p.77-78。
  • response.choices[0].message.content:取得 LLM 回覆文字的寫法 S06 p.79。
