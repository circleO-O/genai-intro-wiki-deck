AI 其實是一個「呆萌的函數」

一句話:AI 模型 = 一台函數學習機 f_θ:你告訴它輸入與輸出長什麼樣子,它學出中間的對應。 S02 p.3
  • 講者把模型比喻成「呆萌型 AI 機器人」(呆一布 DIVE):你要告訴它輸入是什麼、輸出長什麼樣子;它不會分析,沒有意識,不知道自己在做什麼。 S01 p.45S02 p.3
  • 例子:野外拍到一隻八哥,輸入是一張照片,輸出其實是三個數字,分別對應土八哥、白尾八哥、家八哥。 S01 p.46S01 p.48S02 p.11
  • 輸入與輸出都必須是數字(張量);圖片有 R、G、B 三個通道。 S02 p.9S02 p.10
  • 類別用 one-hot encoding 表示:土八哥 [1,0,0]、白尾八哥 [0,1,0]、家八哥 [0,0,1]。 S02 p.12
  • 神經網路的神經元把輸入乘上權重、加上偏值,再經過激發函數(如 ReLU、Sigmoid)轉換後送出。 S02 p.34S02 p.35S02 p.36S02 p.38
  • 生成式 AI 也是這種呆萌型機器人。 S01 p.49

它怎麼學會?Loss 與梯度下降

一句話:訓練 = 量出「錯多少」(loss),再一步步調整參數讓 loss 變小。 S02 p.73
  • 訓練時會定義 loss function:看神經網路考「考古題」時,答案和正確答案差多少。 S02 p.70
  • 訓練就是調整參數 θ,讓 loss 越來越小,目標是找到使 loss 最小的 θ*。 S02 p.73S02 p.74
  • 梯度下降像「走」向最小值:靠切線斜率判斷方向;但斜率指的方向其實是(局部)極大值的方向,所以要往相反方向走。 S02 p.87
  • 一次走太大會跑過頭,所以步伐乘上一個小數,叫 learning rate。 S02 p.91S02 p.92
  • 不管模型怎麼架、選什麼 loss,都可以用 gradient descent 訓練。 S02 p.104

為什麼 AI 每次回答都不一樣?

一句話:AI 每次答案不同,是因為它「依機率抽」答案;語言模型就是依機率抽字。 S03 p.94S03 p.96
  • 八哥辨識若永遠選最高分(土八哥 0.6),同樣輸入就永遠同樣輸出;但也可以依機率抽:60% 土八哥、30% 白尾八哥、10% 家八哥。 S03 p.94
  • 八哥辨識依機率抽好像沒道理,但若是「咖啡豆處理法推薦 AI」,依機率抽就比較有道理。 S03 p.95
  • 語言模型就是用機率抽字:看前面的字,猜下一個字。 S03 p.96
  • 創作型 AI(如 GAN)還有另一個隨機來源:輸入一個 latent tensor z(「天馬行空的想法」),隨機抽 z 就是隨機性的來源。 S03 p.6S03 p.7S03 p.9
  • temperature 控制隨機程度:大於 1 更隨機、小於 1 更固定;實務上常設 τ=1,想更隨機也只設到 1.1。 S04 p.56S04 p.58
  • top-k:只有機率前 k 名(如 50)的字可被選。 S04 p.60

① 模型怎麼運作

LLM 就是在「猜下一個字」

一句話:LLM 的核心是一個函數:看到前面的字,輸出下一個字;被訓練成「很會接話」。 S04 p.8
  • 訓練資料隨手可得:任何句子都能拆成「輸入—答案」配對。例如「炎龍老師很帥」拆成 (炎,龍)、(龍,老)、(老,師)、(師,很)、(很,帥)。 S04 p.9
  • 只看一個字會出問題:用「今天天氣很好。」訓練,「天」會同時有「天」和「氣」兩個答案,就不是函數。 S04 p.10
  • 所以模型要「有記憶」:除了目前的字,還要把前面的字融合成一個記憶向量一起輸入。 S04 p.11
  • 規模:GPT-2 約 15 億參數,GPT-3 約 1,750 億參數。 S04 p.42S04 p.43
  • 現代 LLM「大概什麼都讀過了」,所以什麼話都接得上。 S04 p.45

它怎麼「看」前文?注意力與 Transformer

一句話:2017 年 Google 提出 Transformer(“Attention is All you Need”),主要想取代 RNN。 S05 p.16
  • 2017 年 Google 發表 “Attention is All you Need”,主要想取代 RNN。 S05 p.16
  • 直覺比喻:q 是「問題」,k、v 是「先備知識」,輸出 h 是「適合這個問題的結果」。 S05 p.17
  • Transformer 一次處理整串字,所以字的先後順序沒被考慮;要另外把「位置」加進去(position encoding)。 S05 p.42

  • 位置向量 p_t 與詞向量 x_t 同維度,直接相加。 S05 p.45

「幻覺」不是 bug,是特性

一句話:LLM 是「作夢的機器」;你要負責讀它寫了什麼。 S06 p.16S06 p.33
  • 引用 Karpathy:LLM 沒有「幻覺問題」;幻覺不是錯誤,而是 LLM 最偉大的特點,LLM 是「作夢的機器」。 S06 p.16
  • 比喻:搜尋引擎是 0% 的夢境(不會創造),LLM 則是作夢的機器。人們真正的意思是「不希望 LLM 助理發生幻覺」。 S06 p.16
  • 最重要的使用技巧:一定要讀它寫了什麼。AI 生成的都是「幻覺」,要用自己的專業判斷合不合適;沒有寫錯不代表寫對了我們的意思。 S06 p.33
  • 人的幻覺也許更嚴重,例如「AI 會的,就以為自己也會了」。 S06 p.17
  • 態度:不要覺得 AI 說的一定對,也不要笑它不知道你知道的東西,你們是夥伴。 S06 p.47

② 怎麼用模型

怎麼跟它講話:Prompt 與人設

一句話:Prompt 只有兩個重點:正確的資訊 + 清楚的指引。 S06 p.35
  • 寫好 prompt 的兩個要素:資訊(提供需要的正確資訊)與清楚的指引(用什麼格式、風格回答)。 S06 p.35
  • 對話其實有三種角色:system 是 ChatGPT 的「人設」、user 是使用者輸入、assistant 是回應。 S06 p.37
  • 人設範例「員瑛式思考產生器」:請用員瑛式思考(什麼都正向思維),以第一人稱、社群貼文口吻說為什麼這是超幸運的事,並以「完全是 Lucky Vicky 呀!」結尾。 S06 p.41
  • 不會寫也不用擔心:可以和 AI 討論、請它收集資訊;最後請 AI 用 Markdown 整理成完整的 system prompt,並記得自己修改。 S06 p.46S06 p.48
  • 一定要讀 AI 生成的東西;例:書名在台灣應為《超譯佛經》《正是時候讀叔本華》,AI 給的不一定對。 S06 p.47

② 怎麼用模型

讓 AI 看懂你的資料:RAG 與記憶

一句話:RAG = 先找出相關資料,再交給 LLM 回答;是降低錯誤的一個方法。 S07 p.3
  • RAG(Retrieval-Augmented Generation)被定位為「一個降低錯誤的方法」;媒體標題把它比喻成大型語言模型的「小抄」。 S07 p.3S07 p.4
  • 資料可以自己貼進 prompt,但「不能叫電腦找嗎?」RAG 就是讓電腦去找。 S07 p.5
  • 關鍵是 embedding 模型:把一段文字轉成向量,是這段文字的特徵代表向量。 S07 p.6
  • 流程:文件變成向量 → 問題也變成向量 → 找最接近的放進 prompt → 結果通常不只一筆,可能要重新排序(Reranking)→ 可再補上下文。 S07 p.18S07 p.19S07 p.20S07 p.21S07 p.22
  • 短期記憶就是這次對話,太長前面也會忘;長期記憶的一個做法是把過去對話做成向量資料庫(RAG)。 S07 p.32S07 p.33
  • 另一條路:CAG,用 KV-Cache 技術把資訊都塞給 LLM(上下文越來越長)。 S07 p.26S07 p.27

從聊天到做事:AI Agent = Model + Harness

一句話:AI Agent = AI Model + Harness:模型負責「想」,Harness 負責「做」。 S08 p.4S09 p.14
  • LLM 本身只會生成文字:不會打開你的資料夾、不會改檔案、不能自己上網查最新資料。 S09 p.13
  • Model 是大腦,負責想(理解、規劃、判斷、生成);Harness 是工作裝備,負責做,把模型說的「我要開這個檔案」真的執行,再把結果回報給模型。 S09 p.14
  • 純聊天是「AI 出一張嘴,事情都你在做」;Agentic 是「你出一張嘴,AI 來完成」。 S09 p.8S09 p.10
  • Harness 的六個組成:工作環境、工具、連接器 MCP、技能 Skills、規則檔(CLAUDE.md / AGENTS.md)、排程。 S09 p.16
  • 好的交辦要說清楚三件事:要什麼成品、有什麼限制、怎麼算做完;重點是不要讓 AI 猜。 S09 p.18
  • 「員工手冊」:在專案資料夾裡寫一本手冊(CLAUDE.md / AGENTS.md),讓 AI 照著做。 S09 p.22

Agent 的設計模式與 Tool Use

一句話:LLM 不太會做的事(精確計算、實際數據、網路搜尋),就不要再逼它了——這就是【Tool Use】工具呼叫的出發點。 S08 p.23
  • 投影片列出 AI Agents 的四個設計模式(標示吳恩達):Reflection、Tool Use、Planning、Multiagent Collaboration。 S08 p.18
  • Reflection:第一個 LLM 產生初稿,第二個 LLM 評估並給改善建議,再修改,可重覆數次。 S08 p.19S08 p.20S08 p.21
  • Tool Use 例子(飲料店):顧客說「我想訂 20 杯麥茶」;LLM 參與兩個階段——先說出要呼叫的工具 quote_order("麥茶", 20),工具回傳 JSON(單價 30、總計 600),再依這些數據回答「沒問題!20 杯麥茶一共 600 元」。 S08 p.24S08 p.26S08 p.27S08 p.29
  • MCP(Anthropic)標準化 LLM 與外部工具、資料來源的互動;A2A(Google)定義代理之間如何交換資訊與協作。 S08 p.31
  • Vibe Coding 適合週末小專案、給自己用的小工具;不適合要正式上線的程式。 S08 p.50S08 p.51

把工作拆成流程:Loop 與 Graph

一句話:先用 Prompt;一直重複同樣的修正就升級成 Loop;各階段標準不同才拆成 Graph。 S10 p.27
  • 做出一版、發現問題、再來一次……「這就是 loop」;只是你自己就是那個 loop。 S10 p.5S10 p.40
  • Loop:把「你一直盯著修」寫成會自己執行的規格,寫一次、跑很多輪。要寫清楚五件事:目標、限制、完成標準、停止條件、觸發。 S10 p.20S10 p.21
  • 檢查分兩種:程式檢查(測試過了沒、每頁有沒有出處)與 AI 審查(內容忠於來源嗎);不要叫 AI 審自己的作品,AI 審查要開新對話,只給成品和來源。 S10 p.22
  • Loop 要有剎車:最多改 3 輪、資料不足就停、注意 token 成本。 S10 p.23
  • Graph:流程由人事先畫好,不能跳關,卡住時退回特定一關(像申請流程:系辦 → 院 → 教務處)。 S10 p.24
  • 好的 graph 是大圈很少轉、小圈轉得很快;錯誤要在離源頭最近的地方抓到;常常轉大圈,代表檢查該往前移。 S10 p.26

風險與自保:該注意什麼

一句話:自保:有個資、機密請不要發問;內容正確、品質與侵權由使用者負責。 S06 p.22S06 p.24
  • AI 的四個風險:濫用(人類有惡意)、錯誤對齊(AI 與人類價值不一致)、錯誤(世界複雜出了沒想到的 bug)、結構性風險(多個 AI Agents 與人類交互)。 S06 p.25
  • 使用者要為侵權、內容與文獻是否正確、品質是否符合需求負責。 S06 p.22
  • 即使不拿去訓練,雲端保存的對話仍可能因帳號被盜、權限設定或系統漏洞外洩;有個資、機密請不要發問,完全在本機執行可避開這層風險。 S06 p.23S06 p.24
  • 更要小心不一定故意做的:DeepSeek 沒公開訓練資料,簡體中文比例可預期更高,會潛移默化影響常使用的人。 S06 p.29
  • 「推理能力強」也是危機:加上思考的模型遇到 H-CoT(劫持思維鏈)攻擊,只有 2% 會拒絕回應(對照:原本 98% 會拒絕)。 S06 p.30
  • 負責任使用七點:辨識生成內容的真實性、資料與隱私、著作權、偏見與公平性、批判性思考、避免惡意用途、永續與環境倫理。 S06 p.32
