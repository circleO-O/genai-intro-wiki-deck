# Loop(Loop Engineering)

## 一句話定義
Loop 是「寫一份會自己執行的規格(目標、完成標準、驗證、停止規則),寫一次、跑很多輪,由系統依檢查結果決定下一步」的做法 [S10 p.18, p.20]。

## 白話解釋(給完全沒學過的人)
就算你已經學會當老闆、把工作交辦清楚,實際上還是自己一直盯:交辦工作 → AI 做出一版 → 你發現問題(檢查)→ 再來一次,講者說「這就是 loop」 [S10 p.5]。例如簡報做出來後,你一直修:第 5 頁字太多、某個數字不知出自哪篇、論文結論講反;「這裡也有 loop——只是你自己就是那個 loop」 [S10 p.40]。

Loop engineering 就是把這個「你一直盯著修」的動作寫成規格,讓系統自己轉。寫 prompt 時你是「黏著劑」,每一輪都要親自寫下一句;寫 loop 時你變成設計者、審查者,只需寫一次 [S10 p.20]。

最早的 loop 只有一行:`while :; do cat PROMPT.md | claude ; done`,同一份 PROMPT.md 每一輪重餵一次;看起來很笨但真的會動 [S10 p.19]。

## 重點
- 「不要寫 prompt,寫 loop」:Boris Cherny 說「我的工作是寫 loop」;Peter Steinberger 說去設計替你下 prompt 的 loop [S10 p.17]。至於「Addy Osmani 於 2026 年 6 月命名 loop engineering」,僅依投影片(p.17)所述,本 wiki 未另行核實 [S10 p.17](依投影片)。
- Loop 也是 prompt,差別在寫的內容:寫 prompt 是「這一輪要做什麼」,寫 loop 是「一份會自己執行的規格」 [S10 p.18]。
- Ralph loop:Geoffrey Huntley 於 2025 年 7 月提出;讓它運作的是 prompt 以外的東西:重複、檢查、用檔案記進度 [S10 p.19]。
- 寫 prompt vs 寫 loop:下一步由誰決定(你讀完再寫 vs 系統依檢查結果);寫幾次(每輪都寫 vs 寫一次跑很多輪) [S10 p.20]。
- 一個 loop 要寫清楚五件事:目標(要什麼成品)、限制(哪些不能動)、完成標準(怎麼算做完)、停止條件(做不到時何時停手)、觸發(什麼時候開始跑);前三件是上單元「當老闆」學過的 [S10 p.21]。
- 檢查分兩種:程式檢查(測試有沒有過、連結斷了沒、每頁有沒有出處)與 AI 審查(內容有沒有忠於來源、說法有沒有講反) [S10 p.22]。
- 不要叫 AI 審自己的作品;AI 審查要開新的對話,只給成品和來源 [S10 p.22]。
- 「做完了」不是 AI 說了算,是腳本說了算;說「檢查一下」不算驗證 [S10 p.14]。
- Loop 要有剎車:硬上限(最多改 3 輪)、資料不足就停(不要用自己的知識硬湊)、會花錢(一個 loop 的 token 遠多於聊天);沒人看管的 loop,就是在沒人看管下犯錯的 loop [S10 p.23]。
- 案例(Loop 版簡報,寫成 SKILL.md):程式檢查含每頁有出處、引用頁面存在、數字找得到、8-15 頁、渲染後無溢出;AI 審查為新對話只給簡報與引用頁;每輪只修檢查報告列出的問題;停止=全過/改滿 3 輪/相關頁面少於 3 頁就一開始停下 [S10 p.41]。
- 實跑:第 1 輪腳本抓到 3 頁溢出、2 處沒出處,審查發現第 6 頁講反;第 2 輪腳本全過,審查發現論文 D 沒用到;第 3 輪補進論文 D 後全過、交件並附檢查報告 [S10 p.42]。
- 升級時機:先用 Prompt;一直重複說同樣的修正時升級成 Loop;loop 每次整份重來、各階段標準不同時拆成 Graph [S10 p.27]。
- 三種做法對照,Loop:流程由 AI 在規格內決定;出錯就整份再跑一輪;人在最後驗收;適合標準明確的重複任務 [S10 p.48]。
- 從圖的角度看:Loop = 在單一節點加一條「回到自己」的邊 [S10 p.25]。
